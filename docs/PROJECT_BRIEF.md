# PROJECT BRIEF — SmartLogBook 2.0

**גרסת מסמך:** 0.1 · **עודכן:** 2026-09-25 · **סטטוס:** שלב 0 (אפיון). סבבי שאלות 1–3 נסגרו.

---

## 1. מטרה

לוגבוק לטייס סימולטור שמנהל "חברת תעופה" וירטואלית.
**המערכת מזהה ומתעדת כל טיסה לבד, מתחילתה ועד סופה.** זה נעשה על ידי צירוף תוכנית הטיסה מ-SimBrief לנתוני המעקב של VATSIM.
בסוף הטיסה הטייס משלים כמה נתונים ידניים, והמערכת סוגרת לטיסה ספר חשבונות (הכנסות והוצאות).
כל הסטטיסטיקות, הדוחות ואבני הדרך נבנים מאותו ספר חשבונות.

## 2. ה-Flow המרכזי

```
SimBrief: תוכנית טיסה חדשה ──┐
                             ├─► התאמה (אות קריאה + מוצא + יעד + CID) ─► מעקב חי
VATSIM: הטייס מתחבר ─────────┘
                                                                            │
 בגייט ► הסעה ► המראה ► טיפוס/שיוט/הנמכה ► נחיתה ► הסעה ► בגייט/ניתוק ◄──┘
                                                                            │
                     ממתינה להשלמה: עלויות GSX + FPM (ידני) ◄───────────────┘
                                                                            │
                     סגירה: כתיבת שורות הכנסה/הוצאה ללוגבוק ◄────────────────┘
```

## 3. החלטות שננעלו (פירוט ב-`DECISIONS.md`)

| # | החלטה |

| ADR-002 | המעקב רץ בענן, **בחינם, ובלי לצרוך מכסות של Vercel.** דוגם רק כשיש טיסה פעילה. השירות עצמו ייבחר בשלב הארכיטקטורה. |
| ~~ADR-003~~ → ADR-019 | **VATSIM קודם, וידני כגיבוי.** תוכנית SimBrief היא חובה. לכל טיסה מקור: נעקבה / חלקית / ידנית. |
| ADR-020 | מחזור חיים: ניתוק מקבל 30 דקות המתנה ואחריהן הטיסה `קטועה`. הסטה עולה כסף. הטופס נפתח ב-IN. תוכנית פגה אחרי 12 שעות. |
| ADR-004 | מחשב ליד הסים הוא המכשיר הראשי (Desktop-first). גם אייפד וגם טלפון נתמכים באופן מלא. |

| ADR-007 | **ספר חשבונות:** בסגירת טיסה כל סעיף נשמר כשורה נפרדת. דוחות רק סוכמים שורות ולעולם לא מחשבים מחדש. |
| ADR-008 | זמן בלוק אמיתי מ-VATSIM מחליף את הזמן המתוכנן בכל חישוב שתלוי בזמן. |
| ADR-009 | אבני דרך אוטומטיות במקום יעדים שהמשתמש מגדיר. |
| ADR-010 | "משימות מיוחדות" יורדות מהמערכת. |

## 4. מקורות הנתונים

| מקור | מה מגיע ממנו |
|---|---|
| **SimBrief** (OFP) | אות קריאה, מוצא, יעד, חלופי, סוג מטוס ורישום, נוסעים, מטען, משקלים (מתוכנן ומקסימום), מרחק, זמנים מתוכננים |
| **VATSIM** (תמונת מצב כל ~15 שניות) | מחובר או לא, מיקום, גובה, מהירות קרקע, כיוון. מהם נגזרים שלבי הטיסה, זמני OUT/OFF/ON/IN אמיתיים ומסלול שטס בפועל |
| **ידני** (בסוף טיסה) | דלק ($), צוות קרקע ($), קייטרינג ($): שלושתם מועתקים מ-GSX Pro. וגם FPM בנגיעה |
| **הגדרות** | טבלת תעריפים שהטייס קובע, למשל תעריף לטון נחיתה או תעריף לשעת צוות |

> VATSIM לא מספק קצב ירידה בנגיעה ולא דלק שנשרף בפועל, ולכן שניהם ידניים.

| תחזוקה | הוצאה | אוטומטי: שעות בלוק אמיתיות × תעריף לפי גודל המטוס | ✅ סעיף מאושר, נוסחה בשלב המנוע |

| **🆕 הקפצת צוות** | הוצאה | אוטומטי: כל הצוות × מחיר בסיס למרחק ההקפצה. מתחת ל-50 NM חינם (ADR-026) | ✅ |
| **🆕 הסטה** | הוצאה | אוטומטי: נוסעים × מחיר בסיס למרחק ליעד המקורי. מתחת ל-50 NM, הסעה באוטובוס (ADR-027) | ✅ |

**עיקרון לכל הסעיפים האוטומטיים:** אין רשימה קשיחה של סוגי מטוסים (היום יש רק 10, וכל השאר נחשבים 737).
העלויות נגזרות ממה ש-SimBrief מספק על כל מטוס: משקלים ומספר מושבים. ככה כל מטוס נתמך.
*(אומת על OFP אמיתי: `max_tow`, `max_ldw`, `oew`, `max_passengers`, `cargo`, `pax_count` קיימים. ראה ADR-024.)*

## 7. עיצוב: דרישות

- **לא "עיצוב של AI".** נכון ופונקציונלי, בלי קישוטים.
- **כיוון: תפעולי / EFB** (ADR-015), בהיר וכהה לפי המכשיר (ADR-016), עברית בלבד (ADR-017).
- **כמה שפחות מסכים.** הצעה ראשונית לאישור במוקאפ:
  1. **טיסה** — אם יש טיסה פעילה, המעקב החי. אם היא נחתה, טופס ההשלמה באותו מסך. אם אין טיסה, הטיסה האחרונה ואבן הדרך הבאה.
  2. **לוגבוק** — רשימה, ופרטי טיסה נפתחים בצד (לא במסך נפרד).
  3. **ניתוח** — סטטיסטיקות, דוחות ואבני דרך עם בורר תקופה. הדוח החודשי הוא הדפסה של המסך הזה.
  4. **הגדרות** — משני, בתפריט.
- עברית RTL.

## 8. דוחות וסטטיסטיקות
